# 叛臣领主与王室正统性 · 设计文档

日期：2026-08-09
状态：已确认，待实现（P2a / P2b 两个增量）

> 本文中所有数值（defiance、路线系数、正统性涨落、公式权重、忠诚基线、收买价）均为**初值**，
> 用于让系统先跑通并可被模拟观测。正式配平在 P4 阶段依据 `campaign-balance.sim.mjs` 的
> 三路线使用占比和统一节奏进行，届时这些数字都可能整体调整。

## 一句话

父亲死后，曾臣服于他的领主们各自独立。玩家要靠打服、说服和收买，把二十名叛臣重新纳入渡鸦家的旗下。

## 目标与非目标

**目标**

- 把「领主」从可花钱招募的中立浪人，改成绑定领地的叛臣 NPC
- 激活死变量 `legitimacy`（王室正统性），让它成为说服路线的核心资源
- 让骑士依附于领主，取消「花钱买骑士」按钮
- 让每块可占领地成为一次人物遭遇，而不是一个匿名守军数字

**非目标（本设计不涉及）**

- 实时化改造（季→环境系数、冷却替代 seasonLocks、离线补算放宽）属于 P1
- 地图分层与扩张（核心城堡 / 附属村镇 / 战略要点）属于 P3
- 数值校准（科技树成本、王冠谷门槛可达性）属于 P4
- 拆分 app.js 属于 P0 收尾，安排在本设计落地之后

## 背景

P0 清理阶段确认了三件事，它们共同决定了本设计的形状：

1. 现有 10 名领主里，4 名（雷纳德、伊莎贝尔、埃德蒙、罗德里克的原型）本来就是「父亲的旧臣」，靠每打赢一仗解锁一名。叙事已经指向叛臣，只是数据层没跟上。
2. `legitimacy` 被 15 处事件读写，却不参与任何结算，也不在 UI 显示——现成的资源槽位。
3. 平衡模拟显示 120 局 0 统一，唯一卡住的门槛是领地数（6.4 / 18）。瓶颈是征服吞吐量，说服路线正好提供第二条推进方式。

## 数据架构

### 真相源

`territory.lordId` 是唯一真相源。领主的辖地列表由 territories 派生，不单独存储，因此不存在双向不同步。

`territory.owner`（势力）保持不变，继续作为渲染、AI、邻接判定的依据。

```js
LORD_DEFS = {                          // 静态定义，取代 OFFICER_DEFS
  bran: {
    name: "布兰·狼牙",
    tier: "liege",                     // liege 大叛臣 | vassal 附庸 | loyal 未叛
    faction: "wolf",
    seat: "highpass",                  // 主城
    liege: null,                       // 附庸指向其主君 id
    oldTie: "父亲的北境边将",           // 与你父亲的旧关系，用于文案与好感初值
    defiance: 78,                      // 基础抵抗值
    routes: { force: 1.0, persuade: 0.2, bribe: 0.3 },
    knights: ["knight_9", "knight_10"],
    portrait: "assets/bran.webp",
    stats: { force: 92, command: 80, scheme: 41, govern: 37, charm: 61 }
  }
}
```

运行时状态继续存在既有的 `s.officers` 数组里（`officer(s, id)`、`ownedOfficers(s)` 等辅助函数无需改动），每条记录新增：

```js
{ rapport: 0, captured: false, submitted: false, promisedFief: null }
```

### 新增辅助函数

- `lordAt(s, territoryId)` — 该地守将
- `lordHoldings(s, lordId)` — 派生辖地列表
- `lordVassals(s, lordId)` — 派生附庸列表
- `lordResistance(s, lordId)` — 当前说服阻力
- `lordBribeCost(s, lordId)` — 当前收买价

## 王室正统性

范围 0–100，开局 35。**它不直接解锁任何东西，只降低所有说服的难度。**

### 涨落

| 事件 | 变化 |
|---|---|
| 收复一块旧土 | +3 |
| 会战胜利 | +2 |
| 兑现封地承诺 | +6 |
| 归还俘虏骑士 | +2 |
| 王室 / 教会事件选择 | +2 ~ +12 |
| 用金币收买领主 | −4 |
| 被反攻丢地 | −3 |
| 处死俘虏 | −5 |
| 背弃封地承诺 | −8 |
| 拒缴王室税 | −12 |

### 说服阻力公式

```
邻近邻地 = 该领主全部辖地的相邻领地并集，去重，排除该领主自己的辖地
邻近压力 = min(20, 邻近邻地中属于玩家的块数 × 4)

说服阻力 = defiance − (正统性 × 0.6 + 好感 × 0.8 + 邻近压力 × 0.5) × routes.persuade
```

阻力 ≤ 0 时可发起「要求效忠」。`routes.persuade === 0` 时阻力恒等于 defiance，因此摄政公爵永远无法被说服。

邻近压力这一项让打仗和说服互相供能：打下他的邻居会让他更容易谈。而屠城式扩张虽然堆邻近压力最快，却持续拉低正统性，最终反噬后面所有人的说服难度。

### 收买价

```
收买价（金币） = defiance × 6 / routes.bribe        // routes.bribe === 0 时不可收买
```

收买立即成立，但 −4 正统性，且忠诚基线只有 30（说服为 65，打服为 45）。收买时必须附带一个封地承诺；承诺未兑现时反噬翻倍（−16 正统性，该领主忠诚归零并可能再叛）。

## 三条收服路线

### 打服

攻城胜利 → 领主被俘 → 四选一处置：

| 处置 | 效果 |
|---|---|
| 接受效忠 | 加入，忠诚 45，带 grievance；辖地归你 |
| 收赎金 | +金币（defiance × 4），−2 正统性，该领主离场 |
| 放逐 | +5 军心，−3 正统性，该领主离场 |
| 处死 | +8 威慑（周边领地 defiance −5），−10 正统性，其骑士全部转为死敌 |

### 说服

派使者累积好感 → 阻力归零后「要求效忠」。

好感来源：使者（每次 +8，有冷却）、归还其俘虏骑士（+12）、兑现旧盟约事件（+15）、打赢其邻居（+5）。

成功后忠诚 65，**辖地与骑士一并带过来，不产生战损**。

### 收买

金币 + 封地承诺，立即压低阻力。见效最快，代价是正统性和忠诚基线。

### 层级联动

- **大叛臣被收服** → 其每名附庸做一次跟随判定：
  ```
  跟随概率 = 0.35 + 正统性/250 + 好感/200 − defiance/300
  ```
  跟随者成建制倒向，不跟随者转为独立叛臣（`liege = null`）。
- **附庸被剥离** → 其主君 `defiance` 按已失去的辖地比例下降，最多降 30%。

因此布兰基本只能硬打，但可以先拆光他五名附庸再谈；艾芙琳三条路都通；公爵必须打——主线的军事高潮得以保留。

## 骑士依附

```js
knight.liegeLordId = "bran"
```

- **打服领主** → 其骑士按 45% 概率被俘（可招降 / 释放 / 处死），其余战死
- **说服领主** → 骑士整批跟随，忠诚继承主君好感
- **处死领主** → 其骑士全部转为死敌，`status: "hostile"`，永不可招募

「招募骑士」不再是花钱按钮，而是收服领主的后果。玩家开局那名死忠骑士 `liegeLordId: "player"`。

## 与现有系统的接口

| 现状 | 改为 |
|---|---|
| `defenderLeader()` 按阵营硬编码 bran / aveline | `lordAt(s, territoryId)`，每块地都有守将 |
| `finishBattle()` 胜后解锁一名 locked 领主（app.js:2374） | 领主被俘 → 四选一处置流程 |
| `recruitOfficer()` 花钱招募中立浪人 | 删除，由说服 / 收买路线取代 |
| `knightAction("recruit")` 花钱按钮 | 骑士可得性由其主君状态决定 |
| 城市行动只剩 `scout` | 恢复 `envoy`，目标是具体叛臣而非匿名城市 |
| `OFFICER_DEFS` | 更名 `LORD_DEFS` 并扩展叛臣字段 |
| 存档 `VERSION = 2` | `VERSION = 3` |

### 存档迁移（v2 → v3）

1. 每块非玩家的可占领地，按名册表补 `territory.lordId`
2. 每条 officer 记录补 `rapport: 0, captured: false, submitted: false, promisedFief: null`
3. `side === "locked"` 的旧臣 → 转为其名册座城的叛臣
4. 已被玩家招募（`side === "player"`）的 maelis / elian → 保留为无封地的己方领主
5. 未招募的 maelis / elian → 从名册移除（其角色由新的叛臣体系取代）
6. 每名骑士按名册补 `liegeLordId`；已属玩家的骑士置为 `"player"`

## 测试策略

**`structure.test.mjs` 新增名册完整性断言**

- 每块非玩家的可占领地都有 `lordId`
- 每个 `lordId` 在 `LORD_DEFS` 中存在
- 主从关系无环，且每个 `liege` 字段指向的领主 `tier === "liege"`
- 每名深写领主的 `portrait` 文件真实存在；浅写领主无立绘时能兜底渲染
- `routes.persuade === 0` 的领主，`lordResistance()` 恒等于 `defiance`

**`campaign-balance.sim.mjs` 扩展**

- 给机器人加上说服路线（有余钱且阻力接近零时派使者）

- 分别统计打服 / 说服 / 收买三条路线的使用占比，任何一条为 0 都说明该路线在实战中不可用

## 增量拆分

每个增量结束时游戏都必须是可玩的。

**P2a · 骨架**

`LORD_DEFS` + `territory.lordId` + 名册分配 + `lordAt` / `lordHoldings` / `lordVassals` 辅助函数 + 打服路线接线（被俘与四选一处置）+ 存档迁移 + 上述三类测试。

完成后游戏行为接近现状，但每块地有了守将，被俘领主有了处置流程。

**P2b · 路线**

说服与收买两条路线 + 正统性接线（涨落表、阻力公式、UI 显示）+ 附庸跟随判定 + 使者行动回归 + 将领页重做（我方领主 / 叛臣名册按阵营分层显示阻力与三路进度 / 骑士按主君分组）。

完成后三条路线齐活。

## 已知风险

- **浅写领主可能沦为换皮守军**。缓解：四种原型给出可感知的行为差异（贪财的开价明显低、观望的容易被说服），并在地图节点上直接显示领主名与倾向。
- **说服路线可能压倒军事路线**，让游戏变成点使者。缓解：使者有冷却和金币成本，好感有上限（单靠使者最多堆到 40），高 defiance 领主必须配合邻近压力才谈得下来。
- **20 名领主的状态膨胀存档体积**。每名领主运行时只有 4 个字段，20 名约 1KB，可接受。
