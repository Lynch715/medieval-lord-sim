# P1 实时化：调度器、连续经济与加冕倒计时 · 设计文档

日期：2026-08-09
状态：已确认，待实现

> 本文中所有数值（计时器间隔、冷却时长、离线上限、加冕时刻、开城门槛）均为**初值**。
> 正式配平由 `tests/campaign-balance.sim.mjs` 驱动，见「验收标准」一节。

## 一句话

把「季」从世界的心跳降级为环境系数，让每个系统按自己的节奏在真实时间里推进。

## 目标与非目标

**目标**

- 消灭 `advanceSeason()` 这个单一心跳，它目前一次性挂了 11 个互不相关的系统
- `s.turn` 从存储状态变为派生值，任何代码都不能再靠调用函数凭空推进世界
- 经济、守军、危机判定全部连续化
- `seasonLocks` 换成按对象的冷却时间戳
- AI 与事件各走独立计时器
- 离线补算从 5 分钟放宽到 2 小时
- 用「公爵加冕倒计时」取代与玩家进度无关的 48 季硬停
- 修复地图邻接的单向声明 —— 这是加冕倒计时能成立的前提

**非目标**

- 不改 AI 的决策质量（AI 从不造兵、从不建设、只打相邻玩家领地 —— 属 P3）
- 不做地图分层与扩张（P3）
- 不实现说服与收买路线（P2b）
- 不拆分 app.js

## 背景

P0 的审计确认：时钟和任务队列是真实时间的，但**所有世界模拟仍挂在 300 秒的季界跳变上**。`advanceSeason()` 里挤着经济结算、AI 行动、事件投放、家臣政治、守军恢复、训练衰减、战争疲劳重置、危机判定、终局判定。中间 299 秒世界是静止的，只有数字在滚。

P0 之后有一个重要变化让本次改造变便宜了：`seasonLocks` 原本有三类消费者（领主行动、领地政策、城市行动），前两类已随死代码删除，**现在只剩城市侦察一处**。

## 玩家节奏定位

单场会话 2~4 小时打完一局。离线只是「中途去吃个饭」的容错，不是放置类游戏的核心玩法。真实时间的作用是让建设、行军、研究、征兵**互相重叠形成调度压力**，而不是把游戏拉长到几天。

## 架构

### 时钟

`s.turn` 不再存储，改为派生：

```js
s.clock = {
  startedAt,        // 战役起点
  elapsedMs,        // 已推进的游戏时间，不含暂停
  lastProcessedAt   // 上次处理到的真实时刻
}

const SEASON_MS = 5 * 60 * 1000;
seasonIndex(s) = Math.floor(s.clock.elapsedMs / SEASON_MS)
seasonOf(s)    = SEASONS[seasonIndex(s) % 4]
yearOf(s)      = Math.floor(seasonIndex(s) / 4) + 1
```

现有那些 `turn >= 5`、`turn % 2` 的事件触发条件读派生值即可继续工作。

### 调度器

```js
s.timers = {
  season:  { nextAt, intervalMs: 300000 },   // 换季 + 季度简报
  aiWolf:  { nextAt, intervalMs:  60000 },
  aiRiver: { nextAt, intervalMs:  75000 },
  aiCrown: { nextAt, intervalMs:  90000 },
  events:  { nextAt, intervalMs: 120000 },
  drift:   { nextAt, intervalMs:   5000 }    // 守军、稳定度、破坏度慢漂移
}
```

主循环：

```js
function advanceWorld(s, now, rng) {
  let guard = 0;
  while (guard++ < MAX_STEPS) {
    const next = 最早到期者 among (timers, running jobs);
    if (!next || next.at > now) break;
    accrueTo(s, next.at);     // 先把连续量累积到该时刻
    fireTimer(s, next, rng);  // 再处理这一步
  }
  accrueTo(s, now);
}
```

与现有 `jobs` 队列同构：两者都是 `nextAt`/`endAt` 驱动，因此离线补算复用同一个循环，不需要第二套逻辑。

`advanceSeason()` 整个函数删除，其挂载的 11 件事各自归位。

### 连续量累积

`accrueTo(s, at)` 按经过的秒数累积：

| 项目 | 现在 | 改为 |
|---|---|---|
| 金币 / 粮食 | 按秒（已实现） | 不变 |
| 知识 | 季界一次性 `+3 + 学宫等级` | 按秒，速率 = `(3 + 学宫总等级 + 驿站道路等级×2) / SEASON_秒数` |
| 仓储损耗 | 季界结算溢出 | 超出容量部分按秒衰减，速率 `max(.05, .18 - 粮仓等级×.018) / SEASON_秒数` |
| 训练度衰减 | 季界 −2 | 按秒线性衰减到同等总量 |

### drift 计时器（每 5 秒）

- 我方领地：稳定度 ≥65 时守军 +1（受上限约束），破坏度递减
- 敌方领地：守军按 `enemyGuardCap` 恢复
- 民心与稳定度向各自基线缓慢回归

原本每季一次的量按 `intervalMs / SEASON_MS` 比例摊薄，保证长期速率不变。

### 危机判定连续化

现在是「连续 3 个季度粮食为 0」→ 崩溃。改为按持续时长：

```js
s.crisis = { famineMs, unrestMs }
```

- 粮食为 0 时 `famineMs` 累加，达到 **15 分钟**触发崩溃
- 民心 <12 时 `unrestMs` 累加，达到 **10 分钟**触发崩溃
- 条件解除即清零

玩家因此能实时补救，而不是等季界宣判。

### 冷却取代 seasonLocks

```js
s.cooldowns = { "scout:wolfden": 到期时间戳 }
```

`seasonLocks` 字段彻底删除。

> **给 P2b 的硬约束**：说服路线的使者冷却必须用 `s.cooldowns`，不得引入任何基于季的锁。

### 队列容量

建设保持每领地一条（限制本身合理且贴合叙事）。研究队列开放并发：

```js
研究并发数 = 1 + Math.floor(学宫总等级 / 5)
```

「扩容队列」本身成为一个成长目标。

### 离线补算

上限 **2 小时**。离线期间：

- **照常结算**：资源、知识、建设、训练、研究、行军、整补、drift
- **不结算**：AI 进攻、随机事件、危机判定
- 回来时生成「你不在时发生了什么」简报，未结算的事件在恢复后正常排队

### 加冕倒计时与终局

```js
s.coronation = { atMs, delayedMs }
```

- 初值：战役起点后 **12 游戏年**（48 季 × 5 分钟 = 4 小时）
- 每攻下一块摄政公爵直辖领地（`duchyroad` / `crownfield` / `kingsford`），加冕**推迟 20 分钟**
- 顶栏常驻显示剩余时间
- 倒计时归零 → 结局 `crowned`（失败：法统旁落）
- 在此之前攻下王冠谷 → 结局 `unified`（胜利）

`MAX_TURNS` 常量删除，`great_lord` / `minor_lord` 两个「打满即结束」的结局随之删除。

### 地图连通性（必须先修，否则倒计时会让游戏必输）

`attackableTerritories` 读的是**出发地**的 `adj` 列表：

```js
return origin?.adj?.includes(id) && !mine.has(id);
```

而 `EXTRA_TERRITORIES` 里 17 个扩展节点各自声明了邻居，7 个原始核心节点的 `adj` 却从未反向补回去 —— 全图共 **43 条单向邻接**。后果是从任何核心领地都打不到扩展领地。

实测：24 块可占领地中，**从开局位置只有 10 块可达**，其余 14 块永远无法进攻。这解释了平衡模拟里「平均只能拿到 6.6 块」—— 分母根本不是 24，而是 10。「复国地图」的扩展部分自引入起就从未生效，玩家看得见、点得开、永远打不着。

修复：在 `TERRITORY_DEFS` 构建完成后做一次对称化归一。

```js
// 邻接必须对称：attackableTerritories 读的是出发地的 adj，
// 单向声明会让目标永远无法被进攻。
Object.entries(TERRITORY_DEFS).forEach(([id, d]) => {
  d.adj.forEach(nb => {
    if (TERRITORY_DEFS[nb] && !TERRITORY_DEFS[nb].adj.includes(id)) TERRITORY_DEFS[nb].adj.push(id);
  });
});
```

修复后 24 块全部可达，平均邻居数 3.3。`crowstep`、`crownfield`、`tradersrest` 三块仍是单通路咽喉点，属于合理的地形设计，不额外改动。

结构测试须加断言锁死对称性，防止今后新增节点时重蹈覆辙。

### 王冠谷开城条件（必须与倒计时一起改）

当前条件是「收复 18 块地 + 威望 60 + 攻城工程 + 主力 80」。平衡模拟显示整局平均只能拿到 6.6 块，**胜利本就不可达**。若只加硬截止而不动门槛，游戏将变成必输。

改为：

| 条件 | 说明 |
|---|---|
| 控制 `duchyroad`、`crownfield`、`kingsford` | 公爵的三块直辖地，兵临城下的自然前提 |
| 威望 ≥ 60 | 不变 |
| 完成攻城工程 | 不变 |
| 主力 ≥ 80 | 不变 |

用「先拔掉公爵的直辖地」取代任意的数量门槛：它是叙事上成立的，可达性明确（三块具体的地，而非一个计数），并且与加冕推迟机制指向同一批目标 —— 玩家为了拖延加冕去打这三块地，同时就在为开城门做准备。

## 迁移（v3 → v4）

1. 由旧的 `s.turn` 反推 `clock.elapsedMs = turn * SEASON_MS`，保证季节与年份不跳变
2. 删除 `s.turn`（改为派生）、`s.seasonLocks`、`s.campaignCooldown` 残留
3. `s.crisis` 从 `{famine, unrest, checkedTurn}` 计数改为 `{famineMs, unrestMs}` 毫秒累计，旧计数按每档 5 分钟折算
4. 初始化 `s.timers`，所有 `nextAt` 设为迁移时刻 + 各自 `intervalMs`
5. 初始化 `s.cooldowns = {}`
6. 初始化 `s.coronation`，`atMs` = 迁移时刻 + (48 − 已过季数) × SEASON_MS
7. 旧存档若已 `ended`，保持结局不变；`great_lord` / `minor_lord` 映射为 `minor_lord` 文案

## 测试策略

**新增 `tests/clock.test.mjs`**

- 给定起点与时间跨度，调度器触发的事件序列与预期一致
- **步进等价性**：同一个种子下，一次性推进 2 小时的结果，必须等于分 120 次每次推进 1 分钟的结果。这是实时化最容易出错的地方（重复结算、漏结算、边界重入）
- 暂停期间时间不流逝；恢复后所有 `nextAt` 与 `endAt` 整体顺延
- 季节与年份在任意时刻都能从 `elapsedMs` 正确派生
- 离线 2 小时不触发 AI 进攻与危机判定，但资源、建设、研究照常结算

**`migration.test.mjs` 加 v3 → v4**

- 中盘存档迁移后季节、年份、进行中任务的剩余时间均不跳变
- `turn` 字段被移除且派生值与迁移前一致

**`campaign-balance.sim.mjs` 改造**

- 从「每轮调用 advanceSeason」改为「按真实时间推进」
- **断言胜利可达**：至少 5% 的局达成 `unified`
- 断言失败可达：`crowned` 与 `collapsed` 都应实际出现
- 断言结局分布不唯一

## 验收标准

- 五套测试全绿（structure / lords / migration / clock / balance）
- 平衡模拟中 `unified`、`crowned`、`collapsed` 三种结局**都实际出现**，且结局分布不唯一
- 浏览器实跑：资源连续增长、季节按时切换并生成简报、加冕倒计时可见且会因攻下公爵领地而延长
- 关闭页面 30 分钟后返回，建设与研究已推进，且未发生 AI 进攻
- v3 存档迁移后季节年份不跳变，`selfCheck` 通过

## 已知风险

- **步进等价性是最大的技术风险**。累积函数若在边界处重复或遗漏结算，离线与在线会产生分歧，且极难排查。缓解：把 `accrueTo` 写成幂等的「累积到某个绝对时刻」而非「累积一段时长」，并用步进等价性测试锁死。
- **连续危机判定可能让崩溃过于容易或过于困难**。缓解：阈值（饥荒 15 分钟 / 民乱 10 分钟）由平衡模拟校准。
- **邻接对称化会显著改变平衡**：可达领地从 10 块变成 24 块，敌方可进攻路径同样翻倍，AI 反攻会变多。缓解：对称化与倒计时必须在同一批改动内落地，并立即用平衡模拟观察结局分布。
- **加冕倒计时可能让节奏过紧**。缓解：推迟机制给玩家可控的调节手段；具体时长由模拟校准。
