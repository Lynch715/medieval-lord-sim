# 经营与战斗回报强化验收

日期：2026-10-07。源码目录为本仓库 src/；index.html 与单文件版均由同一份 sources.json 管理。

## 交付范围

本轮完成建设收益预览、首次收复军资、集中战后结算、伤兵与整补、经营及编成战力贡献，以及弓手压制接骑兵侧翼突破。没有实施第二轮完整经营流派或新增大区统一奖励；核心城堡、要塞、加冕延后等现有战略效果在战报中明确展示。

奖励表（金 / 粮 / 长矛兵）：城堡30/16/3；要塞16/12/5；基础粮产至少25的普通城镇10/30/2；其他普通城镇24/12/2。志愿兵加入出征主军，首次奖励一次性入账。和平收服会登记已收复，但不发武力军资。

老存档兼容以可选字段扩展v8：加载时按初始领地、当前领地和已有victories回填一次性登记；此前没有记载的历史无法凭空重建。新伤兵随军团存档。旧战报仍可渲染。

## 自动化

12套 *.test.mjs 回归通过（包括新增feedback.test.mjs）；新增覆盖：

- 建设预览不修改状态、预览与建成实际产出一致、装备门槛与满级。
- 首次到账、重复结算、夺回重复领地、和平收服后再夺回、历史胜场迁移。
- 单/多军团的阵亡、伤兵、驻防、志愿兵守恒；败退不发奖励且救护率较低。
- 读档后伤兵按兵种归队、恢复任务只执行一次；经营设施改善救护与整补。
- 弓手压制成功/失败、平原/森林、骑兵存活数量门槛、撤退入口不会被挤掉。
- 暂停期间新建任务恢复后保持正常时长；显式结束时间任务同样成立。
- 出征携带的实际粮食进入战报；战后净收支与引擎一致；发展入口正确。

固定种子120局模拟在改动前后分别执行，所有原有平衡断言通过，胜利/时限/崩溃均可达。两次修改后结果相同。结果见balance-before.json、balance-after.json。

## 应用内浏览器

使用 Codex In-app Browser，通过localhost:8788访问，独立于127.0.0.1来源的原有存档创建“验收领主”。没有修改用户原存档。

实际点击完成：农田升级（仓容334→369）、并行募兵、编入主力、暂停排队恢复保持20秒、从地图出征灰麦原、抢占地形、弓手轮射、骑兵突破、胜利结算、转入发展、接受俘虏效忠、伤兵存档重载和自动归队。

灰麦原实战：66人出征，阵亡5、伤兵2、驻防13，新增志愿兵2；即时主军48、守军编成13，整补后主军50，总可战兵63 = 66−5+2。结算实际获得10金、30粮、8威望、5正统性、7军心。
